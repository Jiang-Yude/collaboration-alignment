# 03 · 會議前快速對焦（多方共識會議的進場前準備）

> 這是合作對齊一條龍的階段 ⑤。

---

## 什麼時候用

### 必用（觸發條件）

至少符合兩個：

- 對方是**多人介紹**（A 介紹給 B，B 再介紹給主導者）
- 需求只有一句**模糊描述**（「想跟 AI 結合做 XX」「想做點什麼」）
- 各方**訴求疊在一起**（公益 vs 商業、長期 vs 短期、技術 vs 人味）
- 主導者還沒見過**關鍵拍板人**
- 進場前主導者**不確定要拍什麼板**

### 不用

- 一對一明確需求 → 直接出方案
- 已知細節的續案 → 直接出方案
- 純說明會、非決策會議 → 不需要共識

---

## 跟「遠中近目標對齊」的尺度差異

|  | 本檔（會議前快速對焦） | references/01（遠中近目標對齊） |
|---|---|---|
| 尺度 | **週 → 天**（單一會議準備） | 月 → 年（合作關係目標） |
| 問題 | 明天會議前現在要先做什麼？ | 半年後我們想做到什麼？ |

兩個都用了「遠中近」這個詞，但**指不同的事**。看到「遠中近」要先問尺度。

---

## 三段時程：遠 / 中 / 近（會議準備尺度）

### 遠期：多週前 · 背景建構

> 「先不替任何人做決定，先把該知道的事都知道。」

| Step | 做什麼 | 產出 |
|---|---|---|
| 1 | **多人牽線拓樸盤點**（誰介紹誰、誰拍板、誰熟誰） | 拓樸圖 |
| 2 | **每個人的訴求個別列出**（不替合併、不分主次、矛盾也保留） | 訴求清單（分人） |
| 3 | **跨模型查證背景**（人物、機構、產業、案例、反例） | 背景情報筆記 |
| 4 | **法規邊界先列清楚**（醫療法、化妝品法、個資、廣告、金融等） | 雷區清單 |

產出：**逐字稿組織稿** + **會前準備筆記雛形**

### 中期：一週前 · 收斂與選項

> 「列選項給他們選，不是替他們選好。」

| Step | 做什麼 | 產出 |
|---|---|---|
| 1 | **A 線 vs B 線分軌**（公益訴求 vs 商業訴求分開呈現） | 雙軌戰術 |
| 2 | **三層方案候選**（炫一波 / 折衷 / 長線，預算量級對照） | 三層菜單 |
| 3 | **Demo 三件套清單**（從輕到重，每個 demo 對應一個訴求） | Demo 順序表 |
| 4 | **必問 5 題清單**（現場用來探對方真實意圖、預算、平台、時程） | 探需求問題庫 |
| 5 | **雷區清單**（不要主動講 / 不要講錯 / 不要碰） | 防雷表 |
| 6 | **突發狀況應對表**（對方問 X 怎麼回 / 沒興趣怎麼撤 / 超有興趣怎麼控速度） | 應對 SOP |

產出：**會前準備筆記完整版** + **全資訊素簡報**

### 近期：一天前 · 最後校準

> 「精煉到進場前 5 分鐘讀完、demo 立刻拿得出手。」

| Step | 做什麼 | 產出 |
|---|---|---|
| 1 | **精煉素簡報 7 段**（去戰術細節、留腦袋裡要裝的東西） | 進場校準版 |
| 2 | **必背破冰金句**（坐下就能丟、3 秒建立信任） | 金句庫 |
| 3 | **立即 demo 樣板**（拿得出手的實體 HTML） | demo 檔案 |
| 4 | **部署半私密連結**（demo 公開連結，方便會後分享） | 對外 URL |

產出：**精煉素簡報** + **demo HTML** + **對外 URL**

## 三條心法

### 心法一：不替大家做決定

> 這是要讓大家討論的，主導者只負責**呈現所有可能性**，不要替他們合併。

| 該做 | 不該做 |
|---|---|
| 列選項給對方選 | 直接挑一個方案 |
| 每個人訴求個別列 | 替訴求合併 |
| 提問題請對方回答 | 替對方腦補答案 |
| 計劃確認再執行 | 一氣呵成做完 |
| A 線 B 線並存到現場 | 提早併線 |
| 讓現場「拼出來」 | 替現場拼好 |

**為什麼**：替別人決定 = 剝奪他們的擁有感 = 推進不動。**留討論空間 = 對方覺得是「我們一起做的」**。

### 心法二：不腦補

> 任何訴求都要扎實查證。「我覺得他應該想要 X」是地雷。

具體做法：

- **用另一個 AI 模型做交叉查證**（主寫一個模型、查證換另一個，省 token + 多源交叉）
- **找正反案例**（不只成功、要找失敗的，對方才信你做過功課）
- **法規邊界先列**（醫療／金融／教育／個資／廣告都有特定地雷）
- **撞名查證**（同名品牌全球已有幾個？不查就被打槍）
- **被點名「腦補太多」時立刻停下**，重新派跨模型查證而非繼續猜

### 心法三：新洞察立刻轉 demo

> 對方看實體比聽你講十遍有用。

當主導者有「這個方向會成」的洞察時：

1. **立刻探索 3 個視覺方向**（差異化拉開）
2. **挑一個混搭、迭代 v2 v3 v4**（不要追求一次到位）
3. **加可互動 widget**（讓對方一看就懂「未來感」）
4. **部署對外可看連結**（demo 連結方便對方會後翻看）

別卡在「我先想清楚再做」。**模糊期的最大殺手是想太久**。

## 標準產出清單

（適用任何多方模糊案）

| # | 產出 | 時程 | 用途 |
|---|---|---|---|
| 1 | 逐字稿組織稿 | 遠期 | 純文字錯字修正 + 結構化 |
| 2 | 會前準備筆記（A/B 線雙軌） | 中期 | 七大節戰術 |
| 3 | 全資訊素簡報 | 中期 | 完整參考版（10-12 段） |
| 4 | 案例研究素簡報 | 中期 | 跨模型查證結果整理 |
| 5 | 精煉素簡報 | 近期 | 進場前 5 分鐘讀（7 段） |
| 6 | demo HTML 樣板 | 近期 | 立即可看的實體 |
| 7 | 對外 URL | 近期 | 對方會後可翻看 |
| 8 | 工作日記 | 收尾 | 沉澱可重用的方法論 |

## 觸發詞

| 觸發詞 | 行動 |
|---|---|
| 「多人介紹的案子」「牽線案」 | 走遠期 Step 1 拓樸盤點 |
| 「需求很模糊」「不知道要什麼」 | 走遠期 Step 2 訴求個別列 |
| 「多方訴求衝突」「公益 vs 商業」 | 走中期 A 線 vs B 線分軌 |
| 「進場前準備」「明天就要開會」 | 走近期精煉素簡報 |
| 「想做 demo 給對方看」 | 走近期視覺探索 + 部署 |
| 「腦補太多了」（被點名） | **立刻停下** + 重派跨模型 |
