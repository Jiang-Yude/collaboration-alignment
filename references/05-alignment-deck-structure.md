# 05 · 對齊簡報·標準骨架

> 對齊簡報的七段骨架（提案型）+ 洞察型變體。

---

## 提案型骨架（會議前）

```
1. Hero
   - 標題 + 一句話定位
   - 對象 / 性質 / 版本

2. 開場引言（intro block）
   - 為什麼做這份對齊簡報
   - 哪些是主導者主導、哪些留白給對方

3. 主體：方案／提案內容
   - 主導者主導的部分先定（具體內容）
   - 對方主場用留白方塊標出
   - 視覺上區分主導者（用顏色 / 標籤）

4. 速覽對照（如果有多方案）
   - 5-6 列 × 每 cell 一句話
   - 「一眼看出差別」優先於「完整資訊」

5. 階段藍圖 / 延伸願景（可選）
   - 讓對方看到合作的長線天花板

6. 給對方的開放題
   - 明確列出「希望對方回應什麼」
   - 具體題目（不是空白頁等對方自己想）

7. 內部痕跡（給對方看的版本要拿掉）
   - 修訂日誌、版本演進、跨模型查證紀錄
   - 留在工作日記、不留在簡報
```

---

## 洞察型骨架（會議後）

```
1. Hero
   - 標題 + 對象（會議名稱 / 與會者）

2. 會議脈絡
   - 議題、與會者、時間、決議

3. 主體：四模組洞察
   3.1 角色定位（每個人在合作中的位置）
   3.2 隱性訊號（會議中沒被講出來的線索）
   3.3 執行優先序（紅綠燈）
   3.4 個人代辦標籤（每個人的下一步）

4. 視覺化區塊
   - AB 圖：人關係網路圖 + 議題優先矩陣
   - 紅綠燈 traffic light

5. 對議題的判斷（主導者觀點）
   - 哪些值得推進
   - 哪些暫不推
   - 哪些有疑慮

6. 給對方的回饋邀請
   - 「這個判斷你同意嗎？」
   - 「我有沒有漏掉什麼？」

7. 內部痕跡（給對方看的版本要拿掉）
```

---

## 不要放在對齊簡報的東西

無論提案型或洞察型，以下都**不要放**：

- 修訂日誌（內部痕跡）
- 跨模型共思的過程紀錄
- 「為什麼這樣設計」「為什麼這架構成立」這類元層次論證
- 對對方的「角色設計指南」（顯得主導者在指導對方）
- 「這對對方的意義」這類自說自話（讓對方自己感受意義）

---

## 對齊簡報的長度標準

- **提案型**：對方 5 分鐘內看完
- **洞察型**：對方 10 分鐘內看完

太長 = 對方不會看 = 對齊失敗。每次迭代以**減法**為主（見 references/04 心法 5）。
